# 领导文稿助手设计说明

## 目标与边界

在现有通用评测平台上新增一个独立的“领导文稿助手”。它帮助学校领导以自身岗位和部门职责为上下文，基于参考文件和任务要求起草工作文稿。例如，化学学院党委书记上传党建文件后，可以生成突出实验室安全、危化品管理和基层党组织责任的贯彻落实报告。

首期采用独立直达入口 `/leader-assistant/`。官网、官网导航和产品卡片均不展示入口；获得链接的用户可直接使用。首期不要求、不提供账号登录。

首期不是模板填充或评测产品。它以 AI 自由写作为核心，输出可编辑的正文；不提供正式输出模板、多人协作、审批流、组织权限或跨设备同步。

## 用户流程

1. 用户通过直达链接进入工作台。
2. 用户选择已有身份档案，或新建、编辑、删除身份档案。
3. 用户选择常用任务卡片，或选择自定义任务；可自由补充具体要求。
4. 用户按需上传 PDF、DOCX 或 TXT 参考材料。
5. 系统将身份、任务、要求和材料传给 AI，生成 Markdown 格式的文稿初稿。
6. 用户在页面中编辑文稿，可重新生成全文，或输入补充要求对文稿进行局部改写。
7. 用户可以复制正文或下载 Word 文档；生成记录保存在当前浏览器，可从本地历史再次打开。

## 界面设计

工作台使用已确认的三栏布局：

- 左栏是“我的身份档案”，显示名称、岗位和重点职责，支持新增与切换。
- 中栏是“新建写作任务”，包含当前身份提示、六类任务卡片、自由要求输入区、参考材料上传区与生成按钮。
- 右栏显示生成状态、结果操作和本地最近文稿。

内置任务卡片：文件贯彻落实报告、安全工作部署、领导讲话稿、工作总结、通知/函件和自定义任务。任务卡只提供任务目标和建议结构，用户可修改所有要求。

页面顶栏明确标识“仅限受邀链接访问”和“本地保存 · 无需登录”，并在页面底部说明清除浏览器数据或更换设备后无法恢复数据。

## 身份与本地数据

所有个人数据保存在浏览器 `localStorage`，由独立命名空间隔离，至少包含：

- `profiles`：身份档案，字段为 `id`、`name`、`title`、`organization`、`responsibilities`、`focusAreas`、`writingPreferences`、`notes`、创建/更新时间。
- `drafts`：本地草稿，保存未提交任务的身份选择、任务类型、要求和文本。
- `documents`：已生成文稿，保存身份快照、任务快照、附件元数据、AI 初稿、最终编辑稿和时间。

身份档案支持多个。生成时必须持久化身份快照，以避免后来修改档案影响历史文稿的可解释性。

首期不在服务器持久化身份、历史、草稿或用户资料。页面刷新和同一浏览器的后续访问可恢复本地内容；无痕模式、清理站点数据或更换设备将导致内容不可恢复。这是有意的首期隐私和范围取舍。

## 后端与 AI 生成

新增独立路由组 `/api/leader-assistant`，不修改既有 `/api/evaluate`、`/api/public/jobs` 或已发布的公开评测行为。

首期接口包括：

- `POST /api/leader-assistant/generate`：接收身份快照、任务类型、任务要求和可选附件，返回 Markdown 初稿、标题、使用说明和材料不足提示。
- `POST /api/leader-assistant/revise`：接收当前文稿和用户补充要求，返回修改后的 Markdown 文稿。
- `POST /api/leader-assistant/export/docx`：接收标题与 Markdown 文稿，返回下载用 DOCX 文件。

附件支持 PDF、DOCX 和 TXT，沿用现有受控解析、文件大小限制、临时文件清理与模型调用配置。附件只服务当前请求；生成完成后不会写入用户资料或本地服务器历史。

新增 `leadership_writer.py` 负责构建生成与改写提示词、调用既有重试客户端并验证模型返回。任务类型映射只负责提供建议结构和写作导向，不限制用户的自由要求。

提示词必须将以下内容分层：系统写作规则、可信的产品规则、身份快照、任务要求、未受信任的附件文本。附件文本不得改变系统约束或输出格式。模型必须：

- 使用简体中文输出结构化 Markdown 正文；
- 仅将材料明确陈述的事实、数字、时间和文件依据写为确定内容；
- 材料不足或无法确认时使用“待补充”或“请核实”提示；
- 不伪造政策依据、执行情况、数据、引文或落款信息；
- 以岗位和部门重点调整关注事项，但不将档案中的偏好当成事实来源。

改写接口沿用同一安全边界：当前文稿和补充要求均被视为受限输入，不得覆盖系统规则。

## 前端实现

在现有公开前端旁新增一个独立 Vite/React 前端，构建基础路径为 `/leader-assistant/`。它只通过 nginx 的对应路径暴露，不向 `website` 添加链接。

主要模块：

- `ProfileLibrary`：身份档案的 CRUD、校验和切换。
- `TaskComposer`：任务卡、自由要求、文件选择与提交。
- `DocumentEditor`：Markdown 文稿编辑、全文重生成、局部改写、复制和 Word 下载。
- `LocalDocumentHistory`：浏览器本地的任务与文稿记录。
- `leaderStorage` 和 `leaderApi`：分别封装本地数据与独立后端调用。

任务提交前校验：必须选定身份、必须有任务类型和任务要求；附件仅接受允许类型与大小。生成期间禁用重复提交并呈现可理解的进度状态。

## 错误处理

- 不支持的文件、超过限制的文件或解析失败：明确定位到文件并允许移除后重试。
- 模型调用失败或超时：保留用户输入和当前草稿，给出重试按钮，不把失败结果写入历史。
- 返回格式异常：后端拒绝不符合合同的结果并返回通用、可操作的错误消息。
- 浏览器存储配额不足：提示用户导出或删除历史文稿；不静默丢弃当前编辑文本。
- Word 导出失败：保留编辑器内容，提示稍后重试或使用复制功能。

## 验证范围

后端测试覆盖输入校验、身份上下文注入、任务卡提示、附件解析、提示注入防护、材料不足处理、失败重试和 DOCX 导出。

前端测试覆盖访客直达、身份档案 CRUD/切换、六种任务选择及自定义要求、字段校验、本地草稿与历史恢复、生成/改写失败状态、复制和下载操作。

构建与部署验证覆盖独立前端构建、nginx `/leader-assistant/` SPA 回退、官网无入口，以及既有前端与后端测试不回归。

## 后续演进（不在首期）

若实际使用证明需要跨设备保存，可新增可选注册/登录：服务器端账号、密码哈希、个人资料库和将本地数据迁移到账号的机制。该演进不改变首期的直达访问和访客写作能力。
