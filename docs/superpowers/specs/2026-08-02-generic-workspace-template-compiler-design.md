# 通用评估工作区与多类型模板编译器设计

## 1. 背景

当前公开自动评估平台已经能够接收评估目标、待评估材料、评估依据以及 DOCX/PDF 输出模板，并生成结构化评估结果和模板文书。真实测试暴露出两个关键限制：

1. 复杂 Word 模板不能只依赖占位符或可见文字锚点。下划线空白、分段日期、复选框、表格重复行等结构需要精确定位和确定性写回。
2. 当前匿名任务保留 24 小时。新建评估时必须重新上传固定的评估标准和输出模板，不适合长期重复使用同一套制度与文书的用户。

消防整改通知书只是一个例子。平台还应支持员工违规处罚、质量问题整改、供应商准入、合同审查、项目验收等领域。用户提供事实材料、判定规则和期望文书，系统依据规则形成建议，并以用户指定的文字、Word 或 PDF 形式输出。

本设计扩展现有通用评估流程，建立匿名长期工作区、可复用资源库、业务方案库和通用模板编译器。

## 2. 设计目标

- 支持自由描述型文字模板、固定字段型文字模板、DOCX 和 PDF 模板。
- 使用统一模板中间表示描述不同文档中的字段语义、填写策略和写入位置。
- AI 负责事实理解、规则评估、文书适用性判断和结构化字段建议。
- 确定性渲染器负责向 Word/PDF 的准确位置写入内容，不让模型直接编辑二进制文档。
- 材料不足时明确标记待人工补充，不生成看似成功但内容为空的正式文书。
- 固定评估标准、输出模板和业务方案可以长期复用；单次敏感材料和结果仍默认保留 24 小时。
- 不强制注册账号，通过不可猜测的工作区链接和恢复码提供长期访问能力。
- 兼容当前一次性匿名评估流程，并为以后接入正式账号体系保留升级路径。

## 3. 已确认的产品决策

### 3.1 匿名长期工作区

- 用户无需注册账号即可创建工作区。
- 创建时一次性显示专属访问链接和恢复码，服务端只保存恢复密钥哈希。
- 恢复码丢失后平台不能代为找回。
- 固定标准、模板和业务方案保存在工作区中。
- 工作区一年无访问后进入 30 天待清理宽限期；宽限期内成功访问会恢复为正常状态并重新计算一年期限，宽限期结束后执行幂等删除。

### 3.2 文字输出模板

文字模板同时支持两种模式：

1. **自由描述**：例如“生成员工处罚建议书，包含违规事实、制度依据、处罚建议、整改要求和申诉说明”。系统生成结构化文书草稿并导出 DOCX/PDF。
2. **固定字段**：例如“员工姓名、违规事实、制度条款、处罚结果、送达日期”。系统严格按字段生成，适合长期复用。

### 3.3 材料不足策略

- AI 不得推测缺失的行政信息、身份信息、编号、签名或关键事实。
- 缺失字段显示为“待人工补充”。
- 必填项未完成时只能保存和下载带状态标识的草稿，不能确认定稿。
- 文书缺乏适用条件或关键证据时，状态为“暂不能生成”，不输出一份几乎未填写的正式模板。

### 3.4 资源复用

- 评估标准和输出模板可以分别保存并自由组合。
- 常用的评估目标、标准和模板组合可以保存为业务方案。
- 新任务可以使用业务方案一键初始化，也可以从标准库和模板库分别选择。
- 临时上传或文字输入的标准/模板可选择“仅用于本次”或“保存到工作区”。

### 3.5 保存期限

- 工作区固定资产长期保存，并遵循“一年无访问 + 30 天宽限期”的工作区清理规则。
- 单次上传的员工材料、现场图片、临时附件、评估过程数据和生成文书默认保留 24 小时。
- 用户可以随时删除单项资源、业务方案、任务或整个工作区。

## 4. 总体架构

系统采用“资源库 + 评估内核 + 模板编译器 + 确定性渲染器”架构。

### 4.1 工作区服务

负责匿名工作区创建、恢复码鉴权、活动续期、资源权限和长期清理。工作区本身不等同于一次评估任务。

### 4.2 资源库服务

管理三类固定资产：

- **评估标准**：制度、法律法规、检查要求及文字规则；
- **输出模板**：自由描述、固定字段、DOCX 和 PDF；
- **业务方案**：评估目标、标准版本和模板版本的组合。

资产修改创建新版本，不覆盖已经被历史任务引用的版本。业务方案引用明确的资产版本，并允许用户升级到最新版本。

### 4.3 通用输入解析器

解析图片、PDF、DOCX、TXT 和文字输入，输出带文件、页码、段落或图片编号的来源引用。待评估材料、评估依据和模板内容属于不同信任域，不能互相覆盖系统指令。

### 4.4 通用评估内核

按以下顺序工作：

1. 从待评估材料提取可核验事实；
2. 从评估标准提取判定条件；
3. 逐条形成结论、理由、建议和来源引用；
4. 对每份输出模板判断文书适用性；
5. 仅对适用或可补充后适用的模板生成字段建议。

### 4.5 模板编译器

将文字、DOCX 和 PDF 模板转换为统一模板中间表示。编译器负责识别候选字段、填写动作、选项、重复区域和版面限制。AI 可提出字段语义，但写入位置必须由解析结果和人工确认共同确定。

### 4.6 确定性渲染器

按已确认的模板中间表示写入文档。渲染器不解释业务规则，只执行明确的替换、勾选、插入、复制和坐标覆盖动作，并返回缺失字段、定位失败、溢出和分页变化等质量警告。

## 5. 统一模板中间表示

每个模板版本编译为以下结构：

```json
{
  "template_kind": "text_freeform|text_structured|docx|pdf",
  "language": "zh-CN",
  "document_title": "员工处罚建议书",
  "applicability": {
    "required_facts": ["employee_identity", "violation_fact"],
    "required_basis": ["discipline_rule"],
    "decision_mode": "recommendation|authorized_decision"
  },
  "fields": [
    {
      "key": "disciplinary_action",
      "label": "处罚建议",
      "value_type": "text|multiline|date|number|boolean|single_choice|multi_choice|list|table",
      "required": true,
      "fill_source": "ai|user|ai_then_user|computed",
      "missing_policy": "block_finalize|allow_blank|omit_section",
      "options": ["警告", "记过", "辞退"],
      "placements": []
    }
  ]
}
```

内部字段键使用稳定的 ASCII 标识；用户可见标签和最终内容默认使用简体中文。模板明确要求其他语言时可以覆盖默认语言。

## 6. 支持的填写动作

### 6.1 文字模板

- 自由描述模板生成标题、章节和段落结构；
- 固定字段模板严格按字段顺序输出；
- 支持可选章节、列表、表格和重复项；
- 最终统一导出 DOCX 和 PDF。

### 6.2 DOCX 模板

- `placeholder_replace`：替换 `{{field_name}}`；
- `run_range_replace`：替换带下划线的空白 Run 或指定字符范围；
- `paragraph_insert`：在指定标题、标签或段落后插入内容；
- `date_parts`：分别填写年、月、日等片段；
- `checkbox_select`：将指定 `□` 改为 `☑`，支持单选和多选约束；
- `table_cell_fill`：填写指定表格单元格；
- `table_row_repeat`：按列表复制模板行；
- `header_footer_fill`：填写页眉、页脚；
- `content_control_fill`：填写 Word 内容控件和表单域；
- `section_toggle`：根据适用性保留、删除或标记某个模板章节。

DOCX 定位优先使用 XML 结构路径、段落/Run 指纹和上下文签名，不只依赖容易变化的完整可见文本。

### 6.3 PDF 模板

- 优先识别并填写 AcroForm 表单域；
- 文本型 PDF 使用页码、文本块和矩形区域；
- 扫描 PDF 经 OCR 后产生候选坐标；
- 支持文本、日期、选项勾选、图片和多行区域；
- 坐标、字体、字号、对齐和溢出策略必须经过确认；
- 最终输出保留原 PDF 页面作为底稿。

## 7. 文书适用性与业务决策

每份模板在字段映射前产生独立状态：

- `applicable`：事实和依据足够，可以生成；
- `needs_input`：可以生成草稿，但需要人工补充必填项；
- `insufficient_evidence`：缺少关键证据，暂不能生成；
- `not_applicable`：评估结果不满足该文书的适用条件；
- `failed`：模板解析、映射或渲染出现技术错误。

AI 可以给出处罚、整改或审查建议，但正式业务决定必须由具有权限的用户明确确认。模板字段定义通过 `decision_mode` 区分“建议”和“授权决定”。

例如：

- 员工考勤记录和制度条款足够时，可以生成处罚建议；员工编号和送达日期由人工补充；最终处罚结果由用户确认。
- 只有检查照片但无法确认具体消防违法事实时，不生成责令立即改正通知书；可以生成检查情况摘要，并提示需要补充哪些材料。

## 8. 评估数据流

1. 用户进入工作区并新建任务。
2. 用户选择业务方案，或分别选择/上传/输入评估标准和输出模板。
3. 系统把固定资产版本快照绑定到任务，后续资产更新不改变正在运行的任务。
4. 用户上传本次待评估材料。
5. 评估内核生成事实清单、标准清单、逐条结论和来源引用。
6. 系统为每个模板计算文书适用性和缺失信息。
7. 对可生成模板，AI 按模板字段生成结构化值、来源引用和置信度。
8. 用户在校核工作台确认 AI 字段、填写人工字段和业务决定。
9. 渲染器生成带状态标识的草稿并执行质量检查。
10. 必填项、定位、选项冲突和溢出检查全部通过后，用户确认定稿并下载。

## 9. 前端流程

### 9.1 工作区入口

- 创建新工作区；
- 使用专属链接或恢复码进入已有工作区；
- 首次创建时强提醒保存恢复码；
- 工作区首页显示最近使用的标准、模板和业务方案，不显示已经过期的单次敏感材料。

### 9.2 新建评估

提供两个入口：

1. **使用业务方案**：选择一个已保存组合，只上传本次材料；
2. **自定义评估**：填写目标，在标准和模板步骤分别选择工作区资源、临时上传或文字输入。

临时标准和模板可以在任务创建过程中保存到工作区。新建任务不自动沿用上次任务，避免误用；必须由用户选择业务方案或资源。

### 9.3 模板编译与确认

- 上传新模板后展示编译结果和文档预览；
- 字段按“AI 填写、人工填写、AI 建议后确认、计算字段”分类；
- Word 显示空白位、复选框、表格和段落写入位置；
- PDF 显示页码和矩形区域；
- 低置信度字段、重叠坐标和模糊定位必须显式确认；
- 编译确认后的模板版本可保存到模板库，下次不再重复识别。

### 9.4 校核工作台

- 左侧显示文书预览，右侧显示字段与来源；
- 字段状态分为 AI 已填写、待人工补充、审批确认和无法判断；
- AI 字段显示事实证据、规则依据和置信度；
- 支持编辑、单字段重新生成和恢复 AI 初稿；
- 必填项未完成时禁用“确认定稿”，允许下载带明显状态标识的草稿；
- 不适用或证据不足的模板显示原因和需要补充的材料，不提供空白正式文书下载。

## 10. 数据模型

### 10.1 `public_workspaces`

- `id`：不可猜测工作区 ID；
- `access_secret_hash`：恢复密钥哈希；
- `name`：可选工作区名称；
- `created_at`、`last_accessed_at`、`cleanup_after`；
- `status`：active、pending_cleanup、deleted。

### 10.2 `workspace_assets`

- `id`、`workspace_id`；
- `asset_type`：basis、template；
- `name`、`description`、`tags_json`；
- `current_version_id`；
- `created_at`、`updated_at`、`deleted_at`。

### 10.3 `workspace_asset_versions`

- `id`、`asset_id`、`version_number`；
- `source_kind`：file、text_freeform、text_structured；
- `source_file_path` 或 `source_text`；
- `source_format`、`mime_type`、`size`；
- `parsed_content_json`；
- `compiled_template_json`；
- `compilation_status`、`warnings_json`；
- `created_at`。

资产版本创建后不可原地修改。重新编译或修改字段定义创建新版本。

### 10.4 `workspace_scenarios`

- `id`、`workspace_id`；
- `name`、`goal_template`、`description`；
- `basis_version_ids_json`；
- `template_version_ids_json`；
- `created_at`、`updated_at`、`deleted_at`。

### 10.5 现有任务扩展

`public_jobs` 增加可空的 `workspace_id` 和任务资源快照。现有一次性匿名任务保持 `workspace_id = NULL`。

任务必须保存所用标准版本、模板版本及其编译结果快照。任务过期删除时不删除工作区资产；删除工作区资产也不破坏仍在保留期内的任务快照。

## 11. API 设计

### 11.1 工作区

- `POST /api/public/workspaces`：创建工作区并一次性返回恢复密钥；
- `POST /api/public/workspaces/recover`：使用工作区 ID 和恢复密钥恢复会话；
- `GET /api/public/workspaces/{id}`：读取工作区摘要并续期；
- `DELETE /api/public/workspaces/{id}`：删除整个工作区。

### 11.2 资源库

- `GET/POST /api/public/workspaces/{id}/assets`；
- `GET/PUT/DELETE /api/public/workspaces/{id}/assets/{asset_id}`；
- `POST /api/public/workspaces/{id}/assets/{asset_id}/versions`；
- `POST /api/public/workspaces/{id}/assets/{asset_id}/compile`；
- `GET /api/public/workspaces/{id}/assets/{asset_id}/versions/{version_id}`。

### 11.3 业务方案

- `GET/POST /api/public/workspaces/{id}/scenarios`；
- `GET/PUT/DELETE /api/public/workspaces/{id}/scenarios/{scenario_id}`；
- `POST /api/public/workspaces/{id}/scenarios/{scenario_id}/jobs`：从方案创建任务。

### 11.4 任务扩展

现有 `/api/public/jobs/*` 保留，并扩展为支持：

- 从工作区标准/模板版本绑定资源；
- 提交文字评估依据和文字输出模板；
- 查询每个文书的适用性、缺失项和质量状态；
- 下载草稿和定稿；
- 将本次临时标准或模板保存为工作区资产。

任务接口同时增加 `DELETE /api/public/jobs/{id}`，允许用户在默认期限前主动删除本次材料、过程数据和生成文书。

所有工作区接口使用独立的高熵访问 token。任务 token 不能访问整个工作区。

## 12. 安全与隐私

- 服务端只保存恢复密钥和任务 token 的哈希；
- 工作区资源、任务和生成文件均以不可猜测 ID 隔离；
- 工作区 token 与任务 token 权限分离；
- 固定资产和任务文件使用不同存储目录及清理策略；
- 上传文件继续执行扩展名、MIME、文件签名、压缩炸弹、加密和宏文档检查；
- 文字输入与上传内容均视为不可信内容，不能覆盖系统指令；
- 工作区恢复和资源操作增加速率限制和审计时间戳；
- 删除工作区需要再次验证恢复密钥，并执行数据库与物理文件的幂等清理；
- 产品页面明确说明恢复码不可找回以及单次敏感材料的默认清理时间。

## 13. 错误处理与质量门槛

- 模板解析、字段识别、适用性判断、字段映射、渲染和格式转换分别记录状态；
- 单个候选字段无效时保留其他有效字段，不清空整批识别结果；
- 模板编译失败不影响标准库或其他模板；
- 多模板任务中一个文书失败不影响其他文书；
- 必填字段为空、写入位置不存在、单选多选冲突、PDF 坐标越界、文本溢出或明显分页变化时禁止定稿；
- 文字模板生成结果缺少必需章节时禁止定稿；
- 模板不适用或证据不足属于业务状态，不作为技术故障；
- 转换 PDF 失败时保留可下载 DOCX 草稿并允许单独重试；
- 所有失败返回阶段、错误码、用户可读说明和可采取的下一步操作。

## 14. 兼容与迁移

- 当前匿名一次性任务继续工作，不要求创建工作区；
- 现有 DOCX 占位符和 PDF 坐标模板编译为新的统一中间表示；
- 当前 `docx_inferred` 文本锚点迁移为兼容定位动作，但新模板优先生成结构路径和 Run 范围；
- 已确认模板不会自动改变；用户选择“升级编译器版本”时创建新资产版本；
- `/evaluate_tianxin/` 内部定制平台不在本次改造范围；
- 旧公共报告和历史数据结构保持不变。

## 15. 测试策略

### 15.1 模板编译器

- DOCX 占位符、拆分 Run、下划线空白、分段日期、复选框、表格单元格、重复行、页眉页脚和内容控件；
- PDF AcroForm、文本坐标、扫描 OCR、复选框、越界和重叠区域；
- 自由描述和固定字段文字模板；
- 中文字段标签与稳定内部键；
- 单字段识别失败时保留其他字段。

### 15.2 评估与适用性

- 员工处罚、消防整改和至少一个无关领域的端到端样例；
- 证据充分、材料不足、规则冲突和模板不适用；
- 建议字段与授权决定字段隔离；
- 所有结论保持事实和依据引用。

### 15.3 渲染与质量

- 空白 Run 精确替换和格式保留；
- `□` 到 `☑` 的单选/多选约束；
- 表格重复行、长文本、分页和字体回退；
- 必填项为空时阻止定稿；
- 生成文档与模板视觉差异检查；
- 多模板部分失败和 ZIP 清单。

### 15.4 工作区

- 创建、恢复、续期、丢失凭证、错误凭证和速率限制；
- 资产版本、业务方案、任务快照和删除语义；
- 工作区资产长期保留与任务 24 小时清理互不影响；
- 旧匿名任务兼容回归。

## 16. 验收标准

- 用户可以不登录创建并恢复长期工作区；
- 用户可以保存、搜索、版本化和删除固定标准与模板；
- 用户可以保存并一键复用业务方案；
- 新任务可以混合使用工作区资源、临时文件和文字输入；
- 文字模板、DOCX 和 PDF 使用统一字段确认与校核流程；
- Word 下划线、日期、复选框和表格能在正确位置写入；
- 对证据不足或不适用的正式文书不生成空白定稿；
- 必填人工字段未完成时不能确认定稿；
- AI 建议和用户授权决定在数据与界面上明确区分；
- 单次敏感任务按默认期限清理，固定资产不会随任务删除；
- 现有一次性匿名评估继续可用。

## 17. 建议实施分期

### 第一阶段：工作区与复用

实现匿名长期工作区、标准库、模板库、版本、业务方案和任务资源选择器，解决重复上传问题。

### 第二阶段：模板中间表示与 DOCX 精确填写

建立统一模板模型，优先完成占位符、空白 Run、日期、复选框、表格和文字模板；加入适用性判断和必填定稿门槛。

### 第三阶段：PDF 与高级模板能力

完成 AcroForm、文本/扫描 PDF 坐标、重复区域、视觉差异检查和复杂溢出处理。

三个阶段共享同一数据模型和接口边界，避免后续重写工作区、评估结果或校核工作台。
