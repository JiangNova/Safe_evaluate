# 领导文稿助手登录与导出修复设计

## 目标

为领导文稿助手增加两个固定账号的登录入口，并为每个账号首次登录时预置一份可维护的身份档案；保留原有的多身份新增、编辑、删除、切换与本地历史文稿能力。同时修复 Word 导出中的中文字体、正式文稿排版和 Markdown 加粗星号问题。

## 已确认的体验

- `wanxin / wanxin`：默认身份为“党委书记 · 长沙理工大学人工智能学院”。
- `wanqin / wanqin`：默认身份为“院长 · 长沙理工大学人工智能学院”。
- 默认身份可编辑、可删除，并提供“恢复默认身份”操作。
- 原有“添加身份档案”入口与全部多身份能力必须保留。
- 身份档案、草稿、历史文稿仍仅保存在浏览器，但按登录账号独立隔离。
- 登录验证由后端签发 JWT；生成、改写、Word 导出接口均要求该 JWT，避免只遮住前端页面。

## 设计

### 登录和访问控制

新增领导助手专用账号映射与登录接口。账号信息由后端配置读取，默认仅提供两个已确认账号；登录成功返回带 `leader_assistant` 角色的 JWT 和账号名。前端在 localStorage 保存 token，Axios 拦截器自动附带 `Authorization: Bearer <token>`；鉴权失败时清除会话并回到登录页。

### 默认身份与本地数据隔离

本地存储从单一 `leadership-assistant:v1` 迁移为 `leadership-assistant:v2:<username>` 命名空间。首次进入账号空间时写入对应默认身份，默认身份携带稳定的 `defaultProfileKey`。用户仍可创建任意数量的额外身份；删除默认身份后，档案列表会允许为空，点击“恢复默认身份”才重新写入标准内容，且不会覆盖用户编辑后的现有默认身份。

### Word 导出

导出器设置 A4 页面、常规页边距和明确的中西文字体。标题居中加粗，正文使用中文正文样式、首行缩进和 1.5 倍行距；Markdown 标题采用分级样式。增加行内 Markdown 解析：`**文本**` 生成真正加粗的 run，不把星号写进文档。列表项保留为 Word 列表。

## 验收

1. 未登录不能访问工作台或调用领导助手的生成、改写、导出接口。
2. 两个正确账号能登录，错误密码返回 401。
3. 两个账号分别得到正确默认身份，互不读取对方档案、草稿、历史文稿。
4. 用户可继续新增、编辑、删除多份身份，且能恢复被删默认身份。
5. 导出回读的 docx 不含 `**` 字符；加粗 run、中文字体、标题居中、首行缩进和行距均符合预期。
6. 使用消防方案样例内容导出，并将 DOCX 渲染为 PDF/图片进行人工视觉检查。

## 验证记录

- 本地后端：13 项领导助手路由与写作测试通过。
- 本地前端：12 项测试及生产构建通过。
- 线上：`wanxin / wanxin`、`wanqin / wanqin` 登录成功，错误密码返回 401；导出接口能生成 DOCX。
- Word 回读：无 `**` 字符，加粗 run、宋体、首行缩进与 1.5 倍行距均符合预期。
- 线上 Docker 的 LibreOffice 已将回归 DOCX 转为 PDF，并通过页面图片检查标题、中文字体、层级标题与正文缩进正常。
