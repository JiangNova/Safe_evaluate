# 公共评估图片优化设计

## 目标

在不改变输入依据、输出模板和原始现场照片的前提下，减少大批量现场照片送入视觉模型时的传输量与视觉 token，并让用户能看到任务当前所处的处理阶段。

## 范围与边界

- 仅处理公共评估任务的 `material` 中直接上传的 JPEG/JPG/WebP 现场图片。
- 原始上传文件继续原样保存、报告继续引用原始文件；DOCX、PDF、TXT、评估依据和输出模板不参与任何图片处理。
- PNG 默认直接使用原图，以保护截图、图纸和细小文字；不会进行有损转码。
- 单张图片的现有 50 MB、任务总量 150 MB、单任务文件数 30 的安全限制保持不变。

## 图片副本策略

评估开始且任务取得并发槽位后，后端为每张可优化图片在内存中生成评估副本：

- EXIF 方向被规范化，避免竖拍照片方向错误。
- 仅当最长边大于 2560 像素时等比例缩小至 2560 像素；更小的图片直接使用原始字节。
- JPEG 以质量 90、优化编码输出；WebP 以质量 90 输出。处理失败时静默回退到原始字节，不中断评估。
- 评估副本仅用于调用模型，不写回、不覆盖原图，也不改变下载、模板解析或报告页面的内容。

## 任务阶段

`POST /evaluate` 先写入 `queued`。获得全局执行槽位后依次进入 `preprocessing`、`evaluating`、`mapping`，然后进入既有的 `review` 或 `failed`。前端将这些状态显示为“正在排队”“正在优化评估图片”“正在进行视觉评估”“正在生成模板内容”。

这解决了排队任务被误报为“正在评估”的问题；本版本不提供不可靠的精确排队位次。

## 验收

- JPEG/WebP 大图用于评估时尺寸不超过 2560 px，原始文件字节保持不变。
- 小图、PNG 及解码失败图片原样传给模型。
- PDF/DOCX/模板文件不调用图片副本函数。
- 公共任务 API 和页面能显示四个活动阶段；前端持续轮询直至 `review`、`failed` 或既有最终状态。
