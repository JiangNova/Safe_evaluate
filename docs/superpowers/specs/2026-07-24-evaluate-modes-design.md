# 评估双模式 — 设计文档

**日期**: 2026-07-24  
**状态**: 已批准  
**范围**: 评估页面前端 + 新增汇总页面（后端不变）

---

## 概述

当前评估功能只支持"单次评估"：上传多张图片 → 合并为一份报告。需要新增"分图评估"模式：每个图片独立评估，各生成一份独立报告。

---

## 功能

### 单次评估模式（现有行为，不变）

- 多张图片一起发给 AI → 1 份综合报告
- 默认模式

### 分图评估模式（新增）

- N 张图片 → N 个并发 API 请求 → N 份独立报告
- 显示每张图片的评估进度
- 失败图片自动重试（最多 3 次）
- 全部完成后展示结果摘要

---

## UI 设计

### 1. 模式切换

- 位置：UploadZone 上方
- 形式：两个 Tab — `单次评估`（默认）/ `分图评估`
- 分图模式下底部提示文案变更

### 2. 提交与进度（分图模式）

- N 个请求并发发出
- 实时进度条：`正在评估... (3/5 完成)`
- 每张图状态列表：✅ 完成 / 🔄 评估中 / ⏳ 等待中 / ❌ 失败
- 全部完成后显示「查看全部报告」按钮

### 3. 结果呈现

- 单次模式：完成后显示 ✅ + 「查看报告」按钮 → 跳转 `/report/:id`
- 分图模式：完成后显示结果 + 「查看全部报告」按钮 → 跳转 `/evaluate/summary?ids=xxx,yyy,zzz`

### 4. 汇总页面（新增路由 `/evaluate/summary`）

- 每张图一张卡片：文件名、风险等级、统计（合规/不合规/建议）
- 失败卡片显示错误信息 + 「单独重试」
- 底部「重试全部失败项」按钮
- 点击卡片或「查看报告」→ 跳转 `/report/:id`

---

## 数据流

```
分图评估提交:
  EvaluatePage
    → 并发 N 个 POST /api/evaluate（每个 1 张图）
    → 收集 N 个 {report_id, status, filename}
    → 显示进度 + 完成状态
    → 点击按钮 → navigate(/evaluate/summary?ids=xxx,yyy,zzz)

汇总页:
  SummaryPage
    → 解析 URL ids 参数
    → 并发 N 个 GET /api/reports/:id
    → 渲染卡片列表
```

---

## 边界情况

| 场景 | 处理 |
|------|------|
| 只有 1 张图 + 分图模式 | 正常走分图流程，生成 1 份报告 |
| 汇总页 ids 参数缺失 | 重定向回 `/evaluate` |
| 全部分图失败 | 全部卡片显示失败，提供「重试全部」 |
| 用户刷新提交页 | 状态丢失（和现有行为一致） |
